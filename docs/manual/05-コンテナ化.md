# アプリをコンテナにまとめる

> 把应用打成"能搬运的箱子"(容器镜像)。参考手册是让 Claude Code 现写一个轻量 Dockerfile;**本项目已经有一个现成的 `deploy/Dockerfile`**,而且是**重型 GPU/ML 镜像**,所以这里讲怎么理解它、怎么 build。

## 5.1 本项目的 Dockerfile 长什么样

和普通轻量应用不同,本项目的镜像要装整套深度学习环境:

- **基础镜像**:`nvidia/cuda:12.1.1-cudnn8-devel-ubuntu22.04`(带 CUDA 的 GPU 底座)
- **装的东西**:PyTorch、mmengine/mmdetection(含本地 patch)、spconv、点云相关的编译扩展等一大堆
- **拷进去的代码**:`oneformer3d/`、`configs/`、`tools/`、`deploy/`、`mmcv_compat.py` → `/app`
- **关键**:`/app` 被初始化成一个 **git 仓库**(指向本项目 origin),配合 `entrypoint.sh` 在启动时 `git pull`

> **为什么这很重要**:因为代码通过"启动时 git pull"更新,**改代码不用重打镜像**。镜像只在**依赖/环境变化**(加库、改 Dockerfile)时才需要重 build。日常改代码走 [10](10-更新とトラブル対処.md) 的两步即可。

> **提醒**:这个镜像很大、build 很慢(要装 CUDA 栈、编译若干原生扩展,常要几十分钟)。第一次 build 请耐心等。

## 5.2 打镜像(build)

确认 Docker 已启动,在**项目根目录**执行(注意末尾的 `.`):

```bash
docker build -t forestformer3d:0.1.0 -f deploy/Dockerfile .
```

- `forestformer3d` 是镜像名,`0.1.0` 是版本,自己定。
- `-f deploy/Dockerfile` 指定用哪个 Dockerfile;`.` 是构建上下文(项目根)。

> **关于 `latest`**:参考手册建议别用 `latest`。但**本项目线上部署用的正是 `<YOUR_NAME>/forestformer3d:latest`**——因为代码是靠 git-pull 更新、不靠换镜像 tag,所以这里用 `latest` 是可接受的。给依赖大改的镜像另打版本号便于回滚即可。

## 5.3 试跑一下(可选,需要 GPU)

本项目要真正跑推理需要 GPU + 模型权重,本机通常只能验证"镜像能不能起来":

```bash
# 有 GPU 的机器上(装了 nvidia container toolkit)
docker run --rm --gpus all -p 8000:8000 \
  -e INFERENCE_BACKEND=local -e RESULTS_DIR=/tmp/ffformer_results \
  forestformer3d:0.1.0
```

容器起来后浏览器开 `http://localhost:8000`,能看到页面即说明箱子没问题。看完 `Ctrl + C` 停。

> 没有 GPU 的机器上,`--gpus all` 会失败;此时通常直接跳过本机试跑,推到仓库后靠研究云/超算侧验证([08](08-Rancherで公開.md))。

## ✔ 确认点

- ☐ `docker build` 跑完没报错(耐心等,较慢)
- ☐ `docker images` 能看到 `forestformer3d:0.1.0`
- ☐(有 GPU 时)`docker run` 起来的容器,浏览器能开 `http://localhost:8000`
