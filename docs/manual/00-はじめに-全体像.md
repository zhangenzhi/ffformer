# はじめに ― 全体像

> 本手册记录 **JPeaks-Forest** 平台在北海道大学情報基盤中心「研究云(Rancher/Kubernetes)+ 超算(HPC GPU)」环境上的**真实部署与运维流程**。照着走可以从零把服务跑起来、更新、排错。

> **关于占位符**:本手册不写内部 IP 和项目编号。凡是 `<...>` 形式的都是占位符,替换成你自己环境的实际值(向组内基础设施负责人索取):`<namespace>`(K8s 命名空间)、`<project-id>`(HPC 项目/组号)、`<hpc-user>`(HPC 账号)、`<gpu-queue>`(GPU 队列)、`<hpc-host>`(超算登录节点)、`<public-ip>` / `<intermediate-ip>`(申请到的公网/中间 IP)、`<YOUR_NAME>`(GitHub / DockerHub 用户名)。对外访问一律用**域名**。

## 这套系统是什么

**JPeaks-Forest** 是一个森林点云分析平台:用户上传无人机/LiDAR 点云 → 分割出每棵树(ForestFormer3D 模型)→ LLM/VLM 生成物种·健康·碳分析 → 3D 流式查看器。

它由**两层**组成,分处两套硬件:

| 层 | 跑在哪 | 干什么 |
|---|---|---|
| **前台**(本手册主角) | 研究云 Kubernetes(Rancher 管理,命名空间 `<namespace>`) | 网页服务:接上传、显示进度、看结果、出分析报告。**无 GPU** |
| **后端** | 超算 HPC(PBS 队列 `<gpu-queue>`) | 真正的 GPU 推理(分割 + LLM)。前台通过 SSH 把任务推过去跑 |

```
用户浏览器
   │ HTTPS(域名)
   ▼
[研究云 K8s]  ffformer-tls(nginx TLS) ─► ffformer-infer-base(FastAPI 网页服务)
   │                                              │ SSH/SFTP 投作业
   ▼                                              ▼
  域名 → 公网入口(MetalLB)              [超算 HPC]  PBS→GPU 跑 ForestFormer3D + LLM
```

对外域名:`https://j-peaks-forestformer3d.hucc.hokudai.ac.jp/`

> **打比方**:前台是"店面"(接客、下单、上菜),后端是"后厨"(超算的 GPU 才是真正炒菜的灶)。本手册主要教怎么把"店面"部署到研究云上。

## 本项目的一个关键特点:改代码不用重打镜像

普通流程"改代码 = 重打镜像 + 重推 + 重部署"。**本项目不一样**:镜像 `entrypoint.sh` 在**每次 pod 启动时会 `git pull origin main`**,把最新代码拉进来再启动。

所以**日常更新只需两步**:

```bash
git push origin main                                              # 1. 推代码
kubectl -n <namespace> rollout restart deployment/ffformer-infer-base   # 2. 滚动重启,新 pod 自动拉最新代码
```

镜像只有在**依赖/环境变了**(装新库、改 Dockerfile)时才需要重打。详见 [10](10-更新とトラブル対処.md)。
