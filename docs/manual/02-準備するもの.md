# 準備するもの

> 开工前把账号和工具备齐。这一步卡住就没法往下走,所以逐项打勾确认。
>
> `<...>` 占位符含义见 [00 全体像](00-はじめに-全体像.md) 顶部说明。

本项目是**两层**架构(前台 K8s + 后端 HPC),所以你需要**两套访问权**:研究云(Rancher)+ 超算(HPC)。

## 2.1 账号与访问权

### 必要账号

- ☐ **Anthropic 付费计划**(Claude Pro / Max / Team / Enterprise 任一)或 API Key。免费版用不了 Claude Code。
- ☐ **Rancher** 的 URL 与登录信息(向组内基础设施负责人索取)。
- ☐ **GitHub** 账号,且对代码仓库 `github.com/<YOUR_NAME>/ffformer` 有读写权。
- ☐ **Docker Hub** 账号(镜像仓库 `<YOUR_NAME>/forestformer3d` 用)。
- ☐ **HPC 账号** `<hpc-user>`(超算 GPU 后端用),能 SSH 登录超算、能向 PBS 队列 `<gpu-queue>` 投作业。

### 必要的访问凭据

| 凭据 | 从哪来 | 用途 |
|---|---|---|
| **kubeconfig** | Rancher 网页 → 右上「Download KubeConfig」 | 命令行操作 K8s(`kubectl`)。**会过期**,过期重下 |
| **HPC SSH 私钥** | 你自己生成的 ed25519 密钥,公钥登记到超算 | 前台 pod 连超算投作业(做成 K8s Secret,见 [08](08-Rancherで公開.md)) |
| **命名空间** `<namespace>` | 基础设施负责人告知 | 你所有 K8s 资源都放这个区画 |

> **补充**:Rancher 的 URL、用哪个集群、命名空间 `<namespace>` 是什么,都向组内基础设施负责人确认。本手册假设「Rancher 与命名空间已就绪」。

## 2.2 本机要装的工具

按顺序装。前 4 个是核心,后 2 个按需。

| 工具 | 作用 | 入手 |
|---|---|---|
| **Claude Code** | 写/改代码的 AI | [03](03-ClaudeCode導入.md) 讲 |
| **Docker** | 打容器镜像、本地试跑 | docker.com(Docker Desktop) |
| **kubectl** | 命令行操作 K8s(滚动重启、看日志等) | kubernetes.io,或用 Rancher 网页代替大部分操作 |
| **git** | 拉取 / 推送代码仓库 | git-scm.com |
| (可选)**Node.js 22+** | 仅当用 npm 方式装 Claude Code 时需要 | nodejs.org(LTS)。用原生安装器则不需要 |
| (可选)**rclone** | 超算 ⇔ 研究云 大文件数据传输 | rclone.org |

> **提示**:Docker Desktop 装完要**启动并常驻**(状态栏出现鲸鱼图标才算在跑)。本项目的应用本体是 Python(FastAPI),**不需要**为应用本身装 Node.js——Node 只在你选 npm 方式装 Claude Code 时才用得到。

## ✔ 确认点

- ☐ `claude`、`docker`、`kubectl`、`git` 四条命令在终端里都能跑(`--version` 有输出)
- ☐ 有 Rancher 登录、下载到了 kubeconfig,`kubectl -n <namespace> get pods` 能列出东西(不报 `Forbidden`/`unauthenticated`)
- ☐ 能 SSH 登录超算 `<hpc-user>@<hpc-host>`,`qstat` 有反应
- ☐ Docker Hub 能登录(`docker login`)
