# 4.5 From Zero to End App ― 从零到上线,完整走一遍

> **本章目的**:用一个**全新的小应用**,把「用 Claude Code 生成 → 容器化 → 推仓库 → K8s 部署 → 访问 → 更新回滚」**一条龙**走通。
>
> 和主手册的区别:主手册讲的是**已存在的真实重型项目(JPeaks-Forest)**;这一章用一个**轻量示例**(简单 ToDo 应用),让初学者能独立练手、每步都跑得起来。走通这条,再回去看主手册就顺了。
>
> `<...>` 占位符含义见 [00 全体像](00-はじめに-全体像.md)。

---

## 0. 目标与前提

**做完你会得到**:一个自己写的小 Web 应用,跑在 Rancher(Kubernetes)上、能通过网址访问、能更新、能回滚。

**需要**:账号与工具见 [02 準備するもの](02-準備するもの.md)(Claude Code、Docker、kubectl、git,Rancher 访问权,镜像仓库账号)。

**全流程一张图**:
```
Claude Code 生成 ──► 本机跑通 ──► 打成镜像(Docker) ──► 推到仓库
                                                          │
   浏览器访问 ◄── Rancher 部署 ◄── 写 K8s 清单 ◄──────────┘
```

> 每一步末尾都有「✔ 确认点」。卡住了,把报错原文复制给 Claude Code 问怎么修,是最快的路。

---

## 1. 用 Claude Code 生成应用

新建一个空目录并进去,启动 Claude Code:

```bash
mkdir myapp && cd myapp
claude
```

在对话里这样提要求(具体、分点):

```
用 Node.js 和 Express 做一个简单的 ToDo 网页应用。
・浏览器打开能看到 ToDo 列表
・能从输入框添加 ToDo,勾选标记完成
・端口从环境变量 PORT 读(没有就用 3000)
・另加 GET /healthz 返回 "ok",用于健康检查
初学者能懂就行,文件结构尽量简单。
```

生成后让它解释一下:
```
把你刚建的每个文件的作用,用初学者能懂的话一个个讲一遍。
```

> **两个"必备零件"**:`PORT`(端口从环境变量读)和 `/healthz`(健康检查端点)。它们在后面上 K8s 时是刚需,别省。

**✔ 确认点**
- ☐ 目录里出现了 `package.json`、应用源码等文件
- ☐ Claude Code 能讲清每个文件干嘛

---

## 2. 本机运行验证

上云之前,先在本机跑通。让 Claude Code 告诉你启动方式,通常是:

```bash
npm install      # 装依赖(第一次)
npm start        # 启动
```

浏览器开 `http://localhost:3000`,看到 ToDo 列表即成功;再开 `http://localhost:3000/healthz`,显示 `ok`。

**✔ 确认点**
- ☐ 浏览器能看到应用
- ☐ `/healthz` 返回 `ok`
- ☐ 报错就把错误原文贴给 Claude Code 问"什么意思、怎么修"

---

## 3. 容器化(让 Claude 写 Dockerfile)

让 Claude Code 生成 Dockerfile(轻量、多阶段):

```
给这个应用写一个 Dockerfile:
・镜像尽量小(多阶段构建)
・面向生产
・一起生成 .dockerignore
每行加注释,说明在干嘛。
```

确认 Docker 已启动,打镜像(末尾 `.` 不能少):

```bash
docker build -t <YOUR_NAME>/myapp:0.1.0 .
```

本机验证箱子能起来:

```bash
docker run --rm -p 3000:3000 -e PORT=3000 <YOUR_NAME>/myapp:0.1.0
```

浏览器再开 `http://localhost:3000` 能看到应用即成功,`Ctrl + C` 停。

**✔ 确认点**
- ☐ `docker build` 无错误结束
- ☐ `docker run` 起的容器,浏览器能访问

---

## 4. 推到镜像仓库

镜像要先传到"仓库"Rancher 才能拉。这里用 Docker Hub(也可用 GitHub 的 `ghcr.io`)。

先在 **Docker Hub → Account Settings → Security** 生成一个 **Access Token**(当密码用,比登录密码安全)。然后:

```bash
docker login docker.io -u <YOUR_NAME>        # 密码处粘贴 Access Token
docker push <YOUR_NAME>/myapp:0.1.0
```

> **版本号约定**:每次改动升号(`0.1.0 → 0.2.0`)。少用 `latest`,否则"现在到底跑的哪版"会糊涂。Token/密码别贴进代码、别外传。

**✔ 确认点**
- ☐ `docker push` 完整跑完
- ☐ 在 Docker Hub 页面能看到刚上传的镜像

---

## 5. 让 Claude 写 K8s 清单(Manifest)

告诉 Rancher "这个应用怎么跑",靠一份 YAML 清单(manifest):

```
给这个应用写 Kubernetes 部署清单:
・Deployment(副本 2 个,用 /healthz 做健康检查)
・Service
・Ingress(主机名 <app-host>)
・镜像用 <YOUR_NAME>/myapp:0.1.0
文件放到 k8s/ 文件夹。
```

生成的主要文件:`deployment.yaml`(跑几个、用哪个镜像)、`service.yaml`(集群内入口)、`ingress.yaml`(外部入口=主机名)。

> **健康检查**:K8s 会定期访问 `/healthz` 确认应用是否健康,不健康就自动重启——第 1 步埋的"零件"在这派上用场。

**✔ 确认点**
- ☐ `k8s/` 里生成了 Deployment / Service / Ingress
- ☐ 镜像名、主机名填的是你自己的值

---

## 6. Rancher 部署

1. **建/选命名空间**:Rancher → **Cluster → Projects/Namespaces**,用或建 `<namespace>`。
2. **登记 Registry Secret**(镜像私有时):**Storage → Secrets → Create → Registry**,地址 `docker.io`,填 `<YOUR_NAME>` + Access Token,命名如 `dockerhub-secret`,并在 Deployment 的 `imagePullSecrets` 引用。
3. **Import YAML**:右上 **Import YAML**,命名空间选 `<namespace>`,把 `k8s/` 里的清单整段贴进去(多文件用 `---` 分隔),点 **Import**。

> **⚠️ 本环境的坑:PodSecurity `restricted`**。本命名空间强制 restricted,pod 必须带 `securityContext`,否则起不来。让 Claude Code 在清单里加上:
> ```yaml
> # Pod 级
> securityContext:
>   runAsNonRoot: true
>   runAsUser: 1000
>   seccompProfile: { type: RuntimeDefault }
> # 每个容器级
>   allowPrivilegeEscalation: false
>   capabilities: { drop: ["ALL"] }
> ```
> 直接对 Claude 说:「给这份清单加上满足 PodSecurity restricted 的 securityContext」即可。

> 命令行操作前先 `export KUBECONFIG=<你的 config>`;**token 会过期**(报 `system:unauthenticated`),过期就回 Rancher 重新下载 kubeconfig。

**✔ 确认点**
- ☐ **Workloads** 里应用变绿(Running),Pod 数达到指定(如 2/2)
- ☐ 不绿就点进去看 **Events** 和 **View Logs**(排错见第 8 节和 [10](10-更新とトラブル対処.md))

---

## 7. 访问应用

**方式 A:Ingress(域名)** —— 用第 5 步指定的主机名 `<app-host>`(实际域名向基础设施负责人确认),浏览器打开即可。

**方式 B:还没有入口时(临时验证)** —— Rancher → **Workloads** 打开应用 → `⋮` 菜单选 **Port Forwarding**,把集群里的端口临时转到你本机,用给出的本地 URL 访问。命令行等价:
```bash
kubectl -n <namespace> port-forward deploy/myapp 8080:3000
# 然后开 http://localhost:8080
```

**✔ 确认点**
- ☐ 通过域名或 Port Forward 能打开应用

> 到这一步,你写的应用已经跑在服务器上了 🎉

---

## 8. 更新与回滚

**更新**(改完代码想上线):
```bash
# 1. 让 Claude Code 改代码
# 2. 用新版本号重打并推送
docker build -t <YOUR_NAME>/myapp:0.2.0 .
docker push <YOUR_NAME>/myapp:0.2.0
# 3. Rancher → Workloads → 打开 myapp → 把镜像版本改成 0.2.0 保存
```
K8s 会**滚动更新**(不停机、逐个替换)。

**回滚**(更新后出问题):Rancher 的 Workload 菜单选 **Rollback**,回到上一个正常状态。

> 命令行等价:`kubectl -n <namespace> rollout undo deployment/myapp`

**常见坑**(详见 [10](10-更新とトラブル対処.md)):
| 现象 | 原因 | 处理 |
|---|---|---|
| `ImagePullBackOff` | 拉不到镜像:名字打错 / 没登记 Secret | 核对镜像名;确认 Registry Secret 在 `<namespace>` 里 |
| `CrashLoopBackOff` | 应用自身起不来 | 看 **View Logs**,把日志贴给 Claude Code |
| 一直 `Pending` | 集群资源不够 | 找基础设施负责人 |
| 一直不 Ready | 健康检查没过 | 检查 `/healthz` 是否正常 |
