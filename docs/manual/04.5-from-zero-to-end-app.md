## 0. 这个 app 是什么

**JPeaks-Forest 仪表盘**是整个平台的"店面"——一个网页,用户在这里上传点云、跑分割、看 3D 结果、读 LLM 分析报告。技术构成:

| 部分 | 实际是什么 |
|---|---|
| 前端 | **单页** `deploy/dashboard.html`(3000+ 行,**内联** CSS+JS,无构建步骤) |
| 3D 查看器 | **Three.js r128**(CDN)+ 自制**八叉树(octree)流式**点云查看器 |
| 三个页 | **Import**(上传/管理数据)、**Segment**(跑分割+看进度+看结果)、**Analyze**(LLM 场景分析 + 单树健康) |
| 后端 | **FastAPI** `deploy/server.py`(所有接口)+ `deploy/hpc_backend.py`(把重活投到超算) |

> **一句话架构**:dashboard 是很薄的前台,真正的 GPU 分割和 LLM 跑在超算后端([00 全体像](00-はじめに-全体像.md))。

## 1. 用 Claude Code "生成"出来

这个 app 不是一次写成,而是**和 Claude Code 一轮轮迭代**堆出来的。真实做法:在 `<YOUR_NAME>/ffformer` 目录里跑 `claude`,一块块加功能。典型的提要求方式:

**先搭前端骨架:**
```
做一个单页仪表盘 dashboard.html:顶部 logo,三个页签 Import / Segment / Analyze。
纯单文件、内联 CSS 和 JS,不要构建步骤。风格简洁深色。
```

**再加 3D 查看器:**
```
在 Segment 页加一个 Three.js 的点云查看器:
从 /viewer/{task}/metadata.json 读八叉树元数据,按需拉 /viewer/{task}/tiles/*.bin,
流式加载(只显示子采样,别一次性拉几 GB 的 PLY)。
```

**再加后端接口(FastAPI):**
```
在 deploy/server.py 加接口:上传数据、投分割任务、查任务进度、取结果、
以及 LLM 场景分析 / 单树健康分析。任务投到超算后端 hpc_backend.py。
```

> **关键设计决策(真实经验)**:
> - **单页 + 内联 JS**:整个前端就一个 `dashboard.html`,烤进镜像即走,无需前端构建。代价——**改完内联 JS 必须 `node --check`**(一个撇号写进字符串就能让整段脚本挂掉)。
> - **八叉树流式查看器**:大点云不整包下发,只拉子采样瓦片,几秒出画面。
> - **薄前台 + 重后端**:dashboard 只管交互,GPU 活全甩给超算。

**✔ 确认点**
- ☐ 让 Claude Code 讲清 `dashboard.html` 三个页和 `server.py` 接口的对应关系
- ☐ 改内联 JS 后 `node --check` 通过

## 2. 本机验证

```bash
export INFERENCE_BACKEND=local
export RESULTS_DIR=/tmp/ffformer_results
uvicorn deploy.server:app --host 0.0.0.0 --port 8000
```
浏览器开 `http://localhost:8000`,能看到登录页和三个页签即前台通了。完整推理要 GPU+权重,本机通常只验网页/前端逻辑([04](04-アプリを作る.md))。

## 3. 容器化

dashboard 不单独打包——它**和整个服务一起**装进那个重型 CUDA/ML 镜像(`deploy/Dockerfile`,`nvidia/cuda:12.1.1` base)。`dashboard.html`、`server.py` 等都 `COPY` 进 `/app`,而 `/app` 是个 git 仓库,`entrypoint.sh` 启动时 `git pull`。详见 [05](05-コンテナ化.md)。

```bash
docker build -t <YOUR_NAME>/forestformer3d:0.1.0 -f deploy/Dockerfile .
```

> **正因为 `/app` git-pull**:改 dashboard 只需 push 代码 + 滚动重启,**不用重打这个巨大的镜像**(见第 6 节)。

---

## 4. 推到镜像仓库

```bash
docker login docker.io -u <YOUR_NAME>          # 密码处用 Access Token
docker push <YOUR_NAME>/forestformer3d:0.1.0
```
线上部署实际用 `<YOUR_NAME>/forestformer3d:latest`(代码靠 git-pull 更新,不靠换 tag)。详见 [06](06-レジストリに預ける.md)。

---

## 5. K8s 清单

dashboard 所在的前台 Deployment 是 `ffformer-infer-base`,连同 Service / PVC / Secret 一套。清单细节见 [07](07-K8sマニフェスト.md)。要点:
- **Deployment** `ffformer-infer-base`:跑 `uvicorn deploy.server:app`,端口 8000,健康检查 `/health`
- **PVC** `ffformer-pvc`:挂 `/workspace/data`(模型权重等)
- **Secret** `ffformer-hpc-ssh`:连超算的私钥
- ⚠️ 本命名空间强制 **PodSecurity restricted**,pod 要带 `securityContext`

---

## 6. Rancher 部署上线

在 Rancher 上把前台跑起来、开公网入口。详见 [08](08-Rancherで公開.md)。对外链路:
```
用户 → 域名(HTTPS)→ NAT → 中间IP <intermediate-ip>
     → MetalLB(ffformer-public)→ ffformer-tls(nginx TLS)→ ffformer-infer-base:8000(dashboard)
```

## 8. 真实的日常迭代循环(这一章的重点)

dashboard 的改动几乎每天都在发生。因为 `/app` 会 git-pull,**更新 dashboard 不用重打镜像**,循环极短:

```bash
# 1. 让 Claude Code 改 dashboard.html / server.py
# 2. 内联 JS 改过就检查(血泪教训)
node --check <(内联脚本)          # 或让 Claude Code 帮你 node --check
# 3. 推代码
git push origin main
# 4. 滚动重启,新 pod 自动 git-pull 最新代码
kubectl -n <namespace> rollout restart deployment/ffformer-infer-base
```

几十秒后新 pod 起来、`git pull` 到最新 commit,dashboard 就更新了。出问题 `rollout undo` 回滚。详见 [10](10-更新とトラブル対処.md)。

> **对比**:普通流程改前端要"重打镜像→重推→重部署";我们靠 git-pull 把它压成"push + rollout restart"两步。这是 dashboard 能快速迭代的关键。
